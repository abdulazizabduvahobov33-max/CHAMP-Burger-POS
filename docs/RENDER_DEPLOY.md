# KRUNCH POS — деплой на Render (бесплатно)

Пошаговая инструкция по развёртыванию backend + frontend + PostgreSQL на
[Render](https://render.com) с использованием бесплатного плана. Проект уже подготовлен —
файл `render.yaml` в корне репозитория описывает все три сервиса разом (Render называет это
Blueprint).

## Что нужно знать заранее (ограничения бесплатного плана Render)

- **Backend "засыпает"** после ~15 минут без запросов и "просыпается" ~30–60 секунд при
  следующем обращении — это нормально для бесплатного плана, не ошибка.
- **PostgreSQL на бесплатном плане Render удаляется через 30 дней** после создания, если не
  перейти на платный план. Для демонстрации/портфолио этого достаточно, но не используйте
  бесплатную БД для реальных данных ресторана без плана резервного копирования.
- **Загруженные фотографии товаров (`server/src/uploads`) не сохраняются между деплоями** —
  диск backend-сервиса на бесплатном плане временный (сбрасывается при каждом redeploy/
  перезапуске). Фирменные заглушки KRUNCH по-прежнему будут отображаться, если фото нет —
  инфраструктура загрузки не сломана, просто сами файлы не персистентны на free-плане.
  Для реальной эксплуатации с постоянным хранилищем фото — Render Persistent Disk (платный)
  или внешнее хранилище (S3-совместимое).

Ничего из этого не мешает показать проект клиентам или использовать как портфолио — просто
имейте это в виду.

---

## Шаг 0. Убедитесь, что проект запушен на GitHub

Render разворачивает проект из GitHub-репозитория. Если ещё не публиковали — см. предыдущий
шаг (репозиторий `CHAMP-Burger-POS`). Все файлы, нужные для Render (`render.yaml`,
`server/`, `client/`), уже должны быть в репозитории.

---

## Шаг 1. Создать аккаунт и подключить GitHub

1. Откройте **https://render.com** → **Get Started** (или Sign In, если уже есть аккаунт).
2. Войдите через **GitHub** (кнопка "Sign in with GitHub") — это самый простой способ,
   Render сразу получит доступ к вашим репозиториям.
3. Если попросит — разрешите Render доступ к репозиторию `CHAMP-Burger-POS` (можно выдать
   доступ либо ко всем репозиториям, либо выборочно только к этому одному).

---

## Шаг 2. Развернуть через Blueprint (render.yaml)

1. В панели Render нажмите **New +** (вверху) → **Blueprint**.
2. Выберите репозиторий **CHAMP-Burger-POS** из списка.
3. Render найдёт `render.yaml` в корне и покажет три сервиса, которые он создаст:
   - `champ-pos-db` (PostgreSQL, free)
   - `champ-pos-backend` (Web Service, free)
   - `champ-pos-frontend` (Static Site, free)
4. Render попросит заполнить поля, помеченные как "секретные"/пустые:
   - **SEED_ADMIN_PASSWORD** — придумайте реальный пароль администратора (не `admin123`).
   - **SEED_SELLER_PASSWORD** — пароль демо-кассира (или тоже реальный, если планируете
     использовать этот аккаунт).
   - **CLIENT_URL** и **VITE_API_URL** — на этом шаге оставьте пустыми/пропустите, их адреса
     станут известны только после первого деплоя (см. Шаг 3). Render позволит задеплоить
     Blueprint даже с пустыми `sync: false` полями — просто позже вернёмся и заполним их.
5. Нажмите **Apply** (или **Create New Resources**).

Render начнёт создавать базу данных, затем собирать backend и frontend. Первая сборка
занимает 3–7 минут на каждый сервис — можно наблюдать логи прямо в интерфейсе.

---

## Шаг 3. Связать backend и frontend между собой

Это единственный шаг, который нельзя полностью автоматизировать заранее — адреса `.onrender.com`
становятся известны только после создания сервисов.

1. Откройте сервис **champ-pos-backend** → вкладка **Settings** — скопируйте его URL сверху
   страницы, например `https://champ-pos-backend-xxxx.onrender.com`.
2. Откройте сервис **champ-pos-frontend** → **Environment** → найдите переменную
   **VITE_API_URL** → вставьте `<URL backend>/api`, например:
   ```
   https://champ-pos-backend-xxxx.onrender.com/api
   ```
   Сохраните — Render автоматически пересоберёт frontend (это обязательно: Vite "запекает"
   этот адрес в сборку на этапе build, просто переменной окружения в рантайме недостаточно).
3. Откройте сервис **champ-pos-frontend** → **Settings** — скопируйте его URL, например
   `https://champ-pos-frontend-xxxx.onrender.com`.
4. Откройте сервис **champ-pos-backend** → **Environment** → найдите переменную
   **CLIENT_URL** → вставьте URL frontend'а из пункта 3 (без `/api`, без слэша в конце):
   ```
   https://champ-pos-frontend-xxxx.onrender.com
   ```
   Сохраните — backend перезапустится с новым значением (это нужно для CORS: backend
   разрешает запросы только с адресов, перечисленных в `CLIENT_URL`).

Дождитесь, пока оба сервиса покажут статус **Live** (зелёный кружок).

---

## Шаг 4. Создать первого администратора (запустить seed)

Сразу после первого деплоя в базе данных ещё нет ни одного пользователя — войти в систему
не получится, пока не запустить сид-скрипт один раз.

1. Откройте **champ-pos-backend** → вкладка **Shell** (доступна прямо в браузере).
2. Выполните:
   ```bash
   npm run seed
   ```
3. Дождитесь сообщения об успешном создании администратора и (опционально) демо-кассира —
   логины и пароли те, что вы задали в Шаге 2 (`SEED_ADMIN_LOGIN`/`SEED_ADMIN_PASSWORD` и т.д.).

Если вкладка **Shell** недоступна на вашем плане — временная альтернатива: откройте
**champ-pos-backend** → **Settings** → **Start Command**, замените на:
```
npx prisma migrate deploy && npx tsx prisma/seed.ts && npm run start
```
сохраните (это вызовет один redeploy, сид выполнится при старте), затем **обязательно
верните** Start Command обратно на:
```
npx prisma migrate deploy && npm run start
```
и сохраните ещё раз — иначе сид будет пытаться выполняться при каждом перезапуске (он
безопасен для повторного запуска и не создаст дублей, но это лишняя работа при каждом старте).

---

## Шаг 5. Проверить, что всё работает

1. Откройте URL **champ-pos-frontend** в браузере — должна открыться страница входа KRUNCH.
2. Войдите под администратором (логин/пароль из Шага 2).
3. Проверьте: Dashboard, POS, склад, товары — всё должно работать так же, как в локальной
   разработке.
4. Если backend "спал" (бесплатный план) — первая загрузка может занять 30–60 секунд, это
   нормально.

---

## Обновление после новых изменений

Render по умолчанию включает **автодеплой**: каждый `git push` в основную ветку (`main`)
автоматически пересобирает и обновляет и backend, и frontend. Ничего дополнительно нажимать
не нужно. Отключить/включить автодеплой — Settings → Auto-Deploy у каждого сервиса.

## Частые проблемы

**Frontend открывается, но при входе ошибка сети / CORS.**
Проверьте, что `CLIENT_URL` на backend точно совпадает с реальным адресом frontend'а
(без слэша в конце, с `https://`). После изменения дождитесь, пока backend перезапустится.

**Вход "зависает" / сессия слетает через 15 минут.**
Проверьте, что `VITE_API_URL` на frontend указывает на правильный адрес backend'а и что
после его изменения frontend пересобрался (Render делает это автоматически, но можно
проверить в логах сборки).

**"relation does not exist" в логах backend при старте.**
Миграции не применились. Откройте Shell backend'а и выполните `npx prisma migrate deploy`
вручную, затем проверьте логи ещё раз.

**Собранный backend не стартует, ошибка про `@prisma/client`.**
`postinstall`-скрипт (`prisma generate`) должен был отработать автоматически при
`npm install`. Проверьте лог сборки — если там нет строки `Generated Prisma Client`, откройте
Shell и выполните `npx prisma generate` вручную, затем **Manual Deploy → Clear build cache &
deploy**.
