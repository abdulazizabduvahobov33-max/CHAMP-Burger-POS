# Печать чеков — архитектура

Статус: **архитектура готова, реального принтера пока нет**. Все точки входа (после оплаты,
повтор чека, печать из истории) уже работают и показывают предпросмотр — вместо отправки на
физический принтер. Переход на настоящую печать XPrinter XP-58IIT — это добавление одного
файла-драйвера, без переписывания остального.

## Почему не печатаем напрямую с сервера

Backend работает в облаке (Render). Принтер физически подключён к компьютеру/планшету кассира.
Облачный сервер не может достучаться до USB-устройства в кассе — печать обязана запускаться из
браузера/устройства кассира, не с сервера.

## Рассмотренные способы подключения XPrinter XP-58IIT (58мм, USB)

| Способ | Плюсы | Минусы |
|---|---|---|
| **WebUSB** (браузер → USB напрямую, ESC/POS-байты) | Не требует доп. ПО; полный контроль (обрезка бумаги, денежный ящик) | Только Chrome/Edge; на Windows USB-принтер обычно уже занят системным драйвером — нужна ручная замена драйвера (Zadig) |
| **`window.print()`** через ОС-драйвер (чек как HTML/CSS под 58мм) | Работает в любом браузере; XPrinter обычно ставится как обычный Windows-принтер | Диалог печати при каждом чеке; нет доступа к ESC/POS-командам |
| **Локальный принт-агент** (маленькая фоновая программа на кассе, слушает localhost, говорит с принтером по USB/сети/Bluetooth) | Полный контроль ESC/POS; один и тот же способ для любого типа подключения; так устроены Poster, iiko, r_keeper | Нужна установка один раз на кассу |
| Печать с сервера | — | Не работает: сервер не видит USB-принтер кассира |
| Облачные принт-релеи (PrintNode и т.п.) | Готовое решение | Платная подписка, чужая инфраструктура |

**Выбор:** архитектура строится так, чтобы способ подключения был **подменяемым драйвером**, а не
зашитым в код решением. Целевой вариант для продакшена — локальный принт-агент (полный контроль,
поддержка нескольких принтеров сразу). Первым реальным драйвером (следующий этап) разумно сделать
`window.print()` — он не требует установки ничего на кассу и покроет большинство случаев уже сегодня.

## Как устроено сейчас

```
Sale (из БД) + настройки компании (/api/receipt-info)
        │
        ▼
buildReceiptDocument()   ← чистая функция, ничего не знает о принтерах
        │
        ▼
   ReceiptDocument        ← универсальное описание чека (строки, отступы, обрезка)
        │
        ▼
ReceiptPrinterDriver.print(doc)   ← интерфейс; сегодня одна реализация — превью
```

### Файлы

- `client/src/shared/printing/model.ts` — типы `ReceiptDocument`/`ReceiptLine` и интерфейс `ReceiptPrinterDriver`.
- `client/src/shared/printing/buildReceiptDocument.ts` — `Sale` + настройки → `ReceiptDocument`. Не знает о печати вообще.
- `client/src/shared/printing/drivers/previewDriver.ts` — единственный драйвер сейчас: показывает превью вместо печати.
- `client/src/shared/printing/printerRegistry.ts` — реестр драйверов; здесь же в будущем — выбор принтера по устройству.
- `client/src/shared/printing/usePrintReceipt.ts` — хук `printReceipt(sale)`, которым пользуются все кнопки печати.
- `client/src/shared/printing/ReceiptPreviewDialog.tsx` — окно предпросмотра (смонтировано один раз в `App.tsx`).
- `server/src/modules/settings/settings.service.ts` → `getReceiptSettings()` + эндпоинт `GET /api/receipt-info` — узкий, доступный и SELLER, и SUPER_ADMIN (в отличие от `/api/settings`, который только для админа) набор данных для чека: название компании, адрес, телефон, текст в начале/конце чека.

### Где уже подключена печать

- `PosCart.tsx` — кнопка "Печать чека" в баннере после оплаты; кнопка "Повторить чек" в пустой корзине (доступна весь сеанс, не только 4 секунды после продажи).
- `SaleHistoryDetailDialog.tsx` — кнопка "Печать чека" в деталях любого чека из истории продавца.

Все три вызывают один и тот же `usePrintReceipt().printReceipt(sale)`.

## Как подключить реальный принтер позже

1. Создать `client/src/shared/printing/drivers/browserPrintDriver.ts` (или `webUsbDriver.ts`, или
   `localAgentDriver.ts`) — реализовать интерфейс `ReceiptPrinterDriver` (`id`, `label`, `print(doc)`).
2. Зарегистрировать его в `printerRegistry.ts`.
3. Если драйверов станет больше одного — добавить простой выбор принтера (хранить **на устройстве**,
   в `localStorage`, а не в общих настройках компании: у каждой кассы может быть свой принтер).

Ни кнопки, ни `buildReceiptDocument()`, ни данные о продаже трогать не нужно — это и есть смысл
разделения на слои.

## На будущее — несколько принтеров

`printerRegistry.ts` уже спроектирован как реестр (`Record<string, ReceiptPrinterDriver>`), а не
единственный объект — добавление второго физического принтера (например, отдельный принтер на
кухню) означает второй зарегистрированный драйвер и выбор нужного при вызове `print()`, без
изменения архитектуры.
